# 霓虹旋转木马 · 梦幻夜曲｜双环独立反向旋转修复验收

2026-11-10

## 一、结果

- 建筑主体（屋面、冠顶、灯光、帷幕、中央柱、底座、地面、星空、镜面反射）完全静止。
- 外圈 8 匹木马绕中心顺时针旋转。
- 内圈 4 匹木马绕中心逆时针旋转。
- 两圈使用独立 Pivot 和独立角速度；木马原有上下起伏继续运行。
- 没有使用 scene.rotation.y，也没有旋转整个 carouselStaticRoot、整个建筑或整个底座。
- 木马、材质、灯光、音乐、背景、相机和页面布局均未修改。

## 二、Object3D 层级

实际层级如下：

- **carouselStaticRoot**（原 group，name 已改为 carouselStaticRoot）
  - plinth / deck / base 装饰
  - centralColumn
  - canopy / crown / canopyLights / curtains（冠顶模块内部）
  - **horseRotationRoot**（原 horsesGroup，现在只作为两圈 Pivot 的父级，本身不旋转）
    - **outerHorseRingPivot**，position = (0, 0, 0)
      - outerHorseAssembly01 … outerHorseAssembly08
      - 外圈各姿态/材质的 InstancedMesh
      - 外圈支撑杆 gold / neon / beads mesh
    - **innerHorseRingPivot**，position = (0, 0, 0)
      - innerHorseAssembly01 … innerHorseAssembly04
      - 内圈各姿态/材质的 InstancedMesh
      - 内圈支撑杆 gold / neon / beads mesh

两个 Pivot 都位于旋转木马中心 (0, 0, 0)，不是某一匹马的位置。场景调试数据中已确认：

- outerHorseRingPivot.position = [0, 0, 0]
- innerHorseRingPivot.position = [0, 0, 0]
- group / carouselStaticRoot 的旋转在 30 秒运行中始终为 0。

### 为什么木马仍使用 InstancedMesh

木马原本是两套姿态、按材质分别实例化的 InstancedMesh。为了同时满足独立旋转和性能，本轮按环、按姿态重新拆分：

- 外圈每套姿态 4 个实例；
- 内圈每套姿态 2 个实例；
- 每个环/姿态/材质一个 InstancedMesh，父级为该环 Pivot；
- 每匹木马保留一个 assembly 组，作为该实例的世界变换基准；
- 支撑杆仍然按环合并，父级与同环木马相同。

这保留了原模型结构、鞍布颜色、姿态、缩放和位置，同时避免为单匹马创建独立网格。

## 三、初始变换保留

- 环半径：外圈 5.24，内圈 3.18。
- 木马数量：外圈 8，内圈 4。
- 每匹木马的局部 XZ 位置仍由原来的角度公式产生。
- 缩放：外圈 1.3，内圈 1.1，未变。
- 朝向：仍为原 rotation.y = -angle。
- 姿态与鞍布色序：仍按原来的 horseIndex、variant、saddleColors 规则分配。
- 支撑杆仍使用原来的 x/z、gap、sleeves、螺旋参数和顶部几何；未重新建模。
- 初始世界变换与旧版一致（除两圈开始独立公转外）；截图无木马瞬移、无尺寸变化。

## 四、旋转参数与方向

两个速度在有符号常量中独立配置：

- 外圈：**-0.12 rad/s**
- 内圈：**+0.15 rad/s**

俯视验证约定：相机从 +Y 向 -Y 看，屏幕上方为 -Z，屏幕右侧为 +X。

- 外圈角度递减：+X 侧向 +Z 侧运动，即顺时针。
- 内圈角度递增：+X 侧向 -Z 侧运动，即逆时针。
- 顶视截图 t≈0：outer = -0.18997，inner = +0.23746。
- 同一顶视页面 15 秒后：outer = -2.05340，inner = +2.56675。

速度仍沿用页面开场镜头的 spinMultiplier；开场结束后即为上面配置的稳定速度，没有随机变化。

## 五、30 秒实际运行

在同一 1440 × 900 Chrome 页面中运行超过 30 秒：

| 时间点 | 页面时间 ms | outer 角度 | inner 角度 | group 角度 | 木马 y |
| --- | ---: | ---: | ---: | ---: | ---: |
| 初始采样 | 9786.9 | -0.39237 | +0.49046 | 0 | — |
| 15 秒 | 21239.3 | -1.76721 | +2.20901 | 0 | 1.19290 |
| 30 秒 | 36857.5 | -3.64018 | +4.55022 | 0 | 1.17564 |

- 建筑主体旋转始终为 0。
- 两圈角度持续变化，互不覆盖、互不重置。
- 木马 y 值随时间变化，原有起伏动画仍在运行。
- 页面只有 1 个 audio 元素，初始仍为“点击播放”；音乐源码未改。
- 为让两环各自拥有真实 Pivot 父级，木马实例组按环拆分；draw call 约 271 → 322，三角面、材质、灯光均未增加。

## 六、连续性与 Tab 切换

用隐藏状态事件模拟切换标签页：

- 隐藏前：outer = -0.20334，inner = +0.25417。
- 隐藏 1.2 秒后：outer / inner 均保持完全相同，页面暂停。
- 回到可见状态后：outer = -0.29199，inner = +0.36499。

恢复时没有跳变；主循环原本就把 dt 限制在 0.05 s，并在 visibilitychange 时暂停/恢复。两圈 Pivot 的 rotation 持久化，不会从 0 重置。

## 七、木马自身动画与支撑杆

- 上下起伏公式保持原样：
  - y = baseY + sin(t × speed + phase) × amp
  - 同时保留原有的 rotation.x / rotation.z 轻微倾摆。
- 起伏只作用于每匹木马的 assembly，不作用于支撑杆 mesh，因此支撑杆不跟着上下抖动。
- 每匹木马和支撑杆共享同一个环 Pivot，公转严格同步。
- 结果中支撑杆父级检查：

  - 外圈 gold mesh 的 parent = outerHorseRingPivot
  - 内圈 gold mesh 的 parent = innerHorseRingPivot

- 检查了约 30 秒和多个顶视角；木马身体没有与相邻内/外圈木马发生可见穿插。
- 支撑杆顶部仍进入固定檐口/天花内部；由于上端被屋顶结构遮挡，在正常正面/侧面/仰视画面中没有明显的杆件穿出或悬空。没有改动杆件模型或屋面结构。

## 十、限制与说明

- 两圈现在反向旋转，长期运行会出现各种相对相位；顶视图和 30 秒运行未发现明显的环间穿插，但没有做连续碰撞检测/物理阻挡。如果以后把木马尺寸调大，应重新检查环间净距。
- 木马和支撑杆的顶部与固定屋顶的视觉关系沿用原模型：杆顶隐藏在固定檐口/天花内部；没有为移动杆件新增机械导轨。若以后要求近距机械可信度，可在固定天花下加环形导轨。
- 顶视截图中的冠顶隐藏和时钟标注只用于验收，不属于页面运行状态。
- 本轮没有修改音乐、材质、灯光、背景、相机和模型；只改 src/carousel.js 的木马分组、Pivot 和 update 旋转逻辑。
